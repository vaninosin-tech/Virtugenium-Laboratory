## Required design (all of it)
1. **Simulation clock.** Add to `useStandMotionStore` a monotonic simulation clock `simNowMs()` (milliseconds) driven by one timer (`setInterval` 20-30 ms) that does NOT depend on React or rendering, plus `setSimulationPaused(boolean)`. While paused the clock, pours, deliveries and reaction fields do not advance. `startPour` records `at` in this clock; `pourFraction`/`pouredMl` use it. Rendering paused while the clock runs must not stop delivery. Document the policy for a long stall: delivery is computed from the clock difference, bounded by the remaining pour volume (never doubled).
2. **Atomic delivery step.** One function (suggested name `applyDeliveryEvent(event)` in `tubeSilverRuntime.ts`, called from the single publisher in `tubePourImpact.ts` after `recordDelivery` validates it) updates synchronously and in this order: (a) receiving volume and species via `deliver()`; (b) receiving CONTENTS (composition) via `tryAddToTube`/`addTubeContents` on the FIRST valid event of that pour (the commit moves from the 820 ms timer to the first valid event for ALL experiments if equivalent for experiments 1, 3, 4, else keep their 820 ms commit; in every case a pour whose events are all invalid must never commit contents); (c) the reaction field: lazily create it if absent and apply the event (insert chloride at the event's impact point, local-tube coordinates, at the event's simulation time); (d) append the event id to the applied-event journal (cursor). If any step cannot run, none of them is applied. A repeated event id is rejected with no effect. Lazy creation must neither skip nor duplicate the first event.
3. **Runtime owns the field for stage 3.** `tubeSilverRuntime.ts` holds one `TubeSilverField` per receiving tube (`Map`), created at the first valid event (not at composition change, not at a React mount) using `tubeSilverGeometry.ts` which extracts the exact constants the visuals use today (read `tubeReactionVisuals.ts`: search `new TubeSilverField`, `radius`, `box.min.y`, `fieldHeight`, `effectiveRadius`, `tubeLiquidHeight`; the field is built in tube-local coordinates, `up` and `level` are the local up vector and local liquid level). A runtime `tick(simMs)` (driven by the simulation clock timer, not React) calls `field.advance(0.05, up, level, inletLocal, cumulativeDeliveredMl, agitation, flowMlPerSecond, undefined)` in fixed 50 ms steps; `up` comes from `CLAMP_TUBE_MOUTH.root` (inverse rotation of world up), `level` from `tubeLiquidHeight(tubeAmount(id).volumeMl, effectiveRadius)` in the same local convention the visuals use, `inletLocal` from the event's world impact point via the inverse of `CLAMP_TUBE_MOUTH.root`. Export `silverRuntime = { applyDelivery(event), tick(simMs), field(tubeId), journal(tubeId), diagnostics(tubeId), reset(tubeId?) }`. Only stage 3 uses it; stage 1 and others keep their present path. `reset` is called when a tube is replaced/cleared (sandbox "Новая пробирка", `clearTubeAmount`), and a remount of the receiving visuals must find the same field (never create another).
4. **Diagnostics.** `silverRuntime.diagnostics(tubeId)` returns simulation-time stamps (ms since the pour started): `firstValidImpactMs`, `firstCompositionUpdateMs`, `firstFieldInitMs`, `firstChlorideInsertionMs`, plus the first impact point, delivered ml, surface y, and event ids. All four stamps for the first valid impact must be equal (same event, same simulation time). In dev builds expose it as `window.__silverRuntime`.
5. **Emission versus delivery (source accounting).** Add a per-container source volume in `useReagentStorageStore` (existing store, no disconnected state): initial volume per bottle from the existing initial table (`tubeAmounts` `initial[...]` or reagent config), debited by each event's REQUESTED volume (valid or miss), never twice for the same event id, never below 0 (if the bottle is empty the stream and deliveries stop). A miss does not change receiving volume, composition, or the field, and does not insert chloride. Overflow past tube capacity is debited from the source but not delivered.
6. **Rendering independence.** Delivery, composition, field creation and field stepping must work with no React rendering, no WebGL and no shader compilation (test with fake timers and no DOM). `PourStream.tsx` only draws from the numbers.
7. **Regression tests (`tests/night/wave9runtime/`, deterministic, fake timers)** at least: first valid impact (all four stamps equal); composition and field initialisation on the same event; duplicate events; missed pours (source debited, receiving untouched, no contents commit, no field); source-container volume deduction (single deduction, empty bottle stops); remount (visuals mount again: same field, nothing re-delivered); scene and camera changes; rendering paused while simulation continues; simulation paused; receiving liquid level change (1, 2.5, 4 mL); experiments 1, 3, 4 pour paths produce the same final volumes/species as before (compare with the existing tests); mass conservation 1e-9 at every step; determinism.
