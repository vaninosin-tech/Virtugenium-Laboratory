Read `docs/AGCL_INTERFACES.md` (WAVE 11 OVERRIDE, ownership), `docs/night/wave10c2/REPORT.md` (the optics you build on, the CPU reference `lib/night/render/silverOpticsReference.ts`) and the dumps `docs/night/wave11shared/field_state_*ms.json`. Do not alter chemical production or add AgCl mass or opacity to look whiter.

## Why this task exists
In wave 10 the C2 shader built fine in TypeScript and in the isolated shader tests, yet in the real browser it failed to compile (`'*' : wrong operand types ... highp float and const int`, caused by a bare `5` interpolated into GLSL) and the whole cloud silently disappeared. The coordinator fixed it with a `glf()` literal helper (`lib/tubeSilverVolumeMaterial.ts`). It must become an automated browser requirement.

## Required deliverables
1. **Dev diagnostic tools mounted in the real laboratory scene** (new `src/scenes/laboratory/ui/DiagnosticTools.tsx`, dev build only, one mounting line in `ui/Laboratory.tsx` next to `<DiagnosticCamera />`; you also own `ui/DiagnosticCamera.tsx` for extension, keeping its behaviour): `window.__diag = { pauseSimulation(), resumeSimulation(), setBackground("lab"|"black"|"gray"), setOpticsMode(0..3), setCamera(settings), frozen() }` implemented with the APP's own module instances (a dynamically imported copy of a module in a test page is a different instance and does not see the app state). A background mode "black"/"gray" is a diagnostic backdrop that hides or covers the room behind the tube (for example a large unlit backdrop plane placed behind the tube along the camera ray, or hiding the room meshes, whichever does not touch simulation objects, the tube, the liquid or the shader); "lab" is the unchanged normal scene. It must not change any simulation object, position or clock, and must be fully inert without the dev flag. Pausing uses `setSimulationPaused` from `lib/useStandMotionStore.ts` so the rendered state is frozen while rendering continues, which is how the same state can be captured under several conditions.
2. **Automated runtime validation in a real browser** (`tests/_wave11/validateShaders.mjs`, Playwright with the installed Chrome as in `tests/_trace.mjs`; read that script and the way the coordinator runs it, port 5201, `window.__silverStage = 3`, `window.__silverAgg = 0`, `window.__silverDiag = ""`): load the game, pour NaCl into AgNO3 through the real `runStandAction`, and assert: no console `error` entries and no `THREE.WebGLProgram: Shader Error`; every program in `renderer.info.programs` has `gl.getProgramParameter(program, gl.LINK_STATUS)` true and no `diagnostics` failure; the silver volume mesh `TubeSilverDenseField` exists, is visible and its program is among the compiled ones; the uploaded concentration texture version equals the field's version (use the app-exposed field `window.__silverRuntime.field(id)` and the renderer from `window.__three`); the rendered image is non-empty where suspended AgCl exists: compare a screenshot crop of the tube before the pour and after (e.g. with `window.__silverCloud = false` versus on, same frozen state) and require a measurable pixel difference limited to the liquid region and none outside it; `uCloudOn`, `uHaze` and `uOpticsMode` have the expected values. Output a JSON report and exit non-zero on any failure. Also add a Vitest unit test that extracts the generated GLSL strings (fragment source of `makeSilverVolumeMaterial` for all code paths you can enumerate) and checks the classic mistakes statically (integer literals mixed with floats such as `* 5` without a decimal point, mismatched `#version` usage, `int`/`float` mixing in the uniforms) so the same class of error is also caught without a browser.
3. **Three-background optical comparison** (`tests/_wave11/captureOpticsMatrix.mjs`): reach a chosen simulation timestamp (for example 1500, 3000, 6000, 9000 ms after the NaCl click; use the in-page simulation clock, not wall time), pause the simulation (`__diag.pauseSimulation()`), then for the SAME frozen state capture screenshots of the tube region (same camera via `DiagnosticCamera`, same exposure, same optical coefficients) for every combination of background (lab, black, gray) and optics mode (0 combined, 1 raw concentration, 2 extinction only, 3 scattering only), resume, and continue to the next timestamp. Opacity or coefficients must not be changed per background. Write PNG files with systematic names and a JSON listing the frozen simulation timestamp for each file, and an ffmpeg-ready contact sheet script. The capture also records which background and mode each image belongs to in the PNG file name and the JSON, not only in the overlay.
4. **Performance** (`tests/_wave11/measureFps.mjs`): in real time (no `SLOW` dilation, real window), with the suspended cloud present, measure frame times over at least 600 frames for each optics mode (0, 1, 2, 3), with the cloud off as a baseline, and report median FPS, 10th-percentile FPS (i.e. the 90th percentile of frame time), and the added rendering cost per mode in milliseconds. If the browser exposes `EXT_disjoint_timer_query_webgl2` use GPU timer queries too; otherwise state that the figures are CPU-side frame times.
5. **Optical diagnosis**: on the dumps in the four modes (use the CPU reference) and, where you can express it as numbers, on the real captures (the coordinator will run the scripts and give you the output only in a later wave; you have no browser), decide how much of the weak whiteness comes from insufficient suspended material, from the scattering model, or from the background. Quantify with the reference: the radiance a given AgCl optical depth produces over a black, a neutral gray and a bright-window background (the ratio of cloud contrast to background), the optical depth across the tube needed for a given whiteness, and the optical depth the present dumps actually reach. Report whether the optical coefficients are in the right range for the physical particle concentration, but do not raise opacity to compensate for the bright room.
