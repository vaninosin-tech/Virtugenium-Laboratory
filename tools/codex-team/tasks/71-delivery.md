Problem to fix: for experiment 2 (stage 3) chemistry must follow validated delivery events only. Today the impact is published from a render callback (`useFrame` in `PourStream.tsx`), `deliver()` in `tubeAmounts` is called straight from `publishTubePourImpact`, a tube remount can seed NaCl from `contents`, and the pour completion path only works if a stream frame was rendered (the pour `startPour` still commits contents at 820 ms). Requirements:
1. Single path: bottle pour state (`useStandMotionStore.pour`, `POUR_MS`, `pouredMl(k)`) -> a deterministic simulation-side step function that computes, WITHOUT React or rendering, the delivered volume of that step and the impact point (from the same geometry the stream uses: `CLAMP_TUBE_MOUTH`, tube root matrix, `silverStreamEnd`/`tubeLiquidHeight`) -> `recordDelivery` -> only a valid event may call `deliver()` (receiving volume) and update `tubePourImpact`. The stream drawing consumes the same numbers; the render callback must not be the only thing able to publish. Drive the step function from a lightweight timer (`setInterval` 20-40 ms, started when `pour` appears and stopped when it ends) so delivery completes even if no frame renders; keep `useFrame` for drawing only.
2. Idempotence: the same (serial, step) never delivers twice (React strict mode, remount, double effect). Remounting the tube or re-creating the visuals must not deliver or seed anything (NaCl is never seeded from `contents`; check `seedTubeAmounts` callers).
3. Misses: if the impact point is outside the tube mouth radius or above the liquid surface tolerance, the event is recorded as invalid, the receiving tube gets nothing, the pour still consumes its time. Source accounting: if the code tracks the source bottle volume, subtract the full requested volume; if it does not, say so and propose the smallest change.
4. Level: the receiving liquid level and the surface used for the impact must be the same value (`tubeLiquidHeight` of the current volume); after each valid event the next event's surface is the new level.
5. Pause: if the game/render loop is paused, no delivery advances (use the pour store's own timebase; if it is `Date.now()` based, document the behaviour on a long stall and make the policy deterministic, for example delivery proportional to elapsed pour time capped to the remaining volume).
6. Unit-test everything with fakes (no browser): impact valid/miss/above-surface/no-liquid/outside-tube; duplicate steps; remount (new subscriber) does not re-deliver; stop (pour cleared mid-way) stops delivery and total equals what was delivered; level change; deterministic totals equal `STANDARD_POUR_ML` for a full pour.
7. Preserve experiments 1, 3, 4 behaviour (the legacy `publishTubePourImpact` signature may stay for them if you route it through the ledger with a permissive context, but their tests must stay green). `tsc --noEmit` clean; vitest one process at a time (`--configLoader runner --no-file-parallelism`), whole suite once at the end, rerun timed-out files alone and say so.
