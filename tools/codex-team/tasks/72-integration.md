# Agent 2 "integration": real-game delivery test scenarios and event log (tests + a recorder helper)

Read `docs/AGCL_INTERFACES.md` (WAVE 8 OVERRIDE). The authoritative ledger is `src/scenes/laboratory/lib/tubeDelivery.ts` (read-only for you; Agent 1 is rewriting the pour path around it and may extend it, so code against its exported API: `recordDelivery`, `validateImpact`, `deliveredMl`, `deliveryEvents`, `firstValidDelivery`, `clearDeliveries`, and the types). You own only `tests/night/wave8integration/` and `docs/night/wave8integration/`. Never edit `src/`.

Write the scenario tests the customer demanded, as deterministic unit/integration tests with fakes (no browser, no WebGL). Use `TubeSilverField` in stage 3 (dynamic import after `window.__silverStage = 3`, delete in `afterAll`) driven the way the game drives it (see `tubeReactionVisuals.ts`, search `silverField.advance`: inlet = impact point converted to tube-local, `delivery` = cumulative delivered ml, strength = flow in mL/s). Build a small harness that, per 50 ms step, takes the ledger (`deliveredMl(tubeId, "nacl")`, `firstValidDelivery`) as the ONLY source of delivery for the field, and logs an event table: pour start, stream visible, first valid impact (time, x, y, z, surface y), delivered mL, delivered chloride (`species["Cl-"].total + extent`), first cell where Cl- is positive, first cell where `productSource` is positive.
Scenarios (each its own `it`):
1. Pouring before surface contact: events above the surface tolerance are invalid, `deliveredMl` is 0, Cl- total 0, extent 0.
2. Valid surface impact: first valid event at the surface; first Cl- cell within 3 mm of the impact and in the top two wet rows; first source cell inside Ag+ and Cl- overlap.
3. Missing the tube: impact outside the radius records invalid events, nothing enters, field untouched.
4. Stopping the pour half way: delivery total equals what was delivered, no further Cl- enters, existing species continue to react only where both remain.
5. Remounting the receiving tube (re-create the field and call the seeding functions the game calls; if `tubeAmounts` seeding can add NaCl volume or Cl- without a ledger event, assert it does NOT for stage 3): nothing is delivered twice.
6. Pausing / interrupting rendering: skip steps (call the harness with big gaps and with no render): total delivered must still equal the pour plan, never double.
7. Changing the impact position (left wall, centre, right wall): first Cl- cell and first source cell move with it (signs and monotonic order).
8. Changing the receiving liquid level (1, 2.5, 4 mL): the valid impact y follows the level.
Also assert mass conservation each step (1e-9) in scenarios 2, 4, 6. Report real counts. If a scenario cannot pass because the code is wrong, keep the test, mark it `it.fails` ONLY with a comment naming the exact defect, and list it in `docs/night/wave8integration/REPORT.md` with the minimal repro; Agent 1 and the coordinator will fix and flip it. Export the event table of scenario 2 to `docs/night/wave8integration/events.md`. `tsc --noEmit` clean; vitest one process at a time (`--configLoader runner --no-file-parallelism`), whole suite last, rerun timed-out files alone and say so. No visual claims.
