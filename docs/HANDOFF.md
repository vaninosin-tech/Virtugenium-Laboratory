# Virtugenium Laboratory — состояние и задачи

Документ для передачи работы другому исполнителю (человеку или ИИ-агенту).
Составлен 25.09.2026 по факту разбора кода, а не по ТЗ — где код расходится с ТЗ, указано явно.

---

## 1. Что это

Учебный тренажёр лабораторной работы по химии. Устанавливаемое приложение.
Стек: **Tauri 2 + React 19 + TypeScript + three.js / @react-three/fiber + zustand**, сборка Vite, тесты vitest.

Игрок перемещается между **фиксированными зонами** одной 360°-лаборатории (свободного хождения нет и не будет),
собирает реактивы и оборудование по шкафам, проводит опыт и получает оценку.
Управление — мышь, осмотр через pointer lock, взаимодействие через клики по 3D-объектам.

Четыре опыта. Сейчас работа идёт по первому: **медь + разбавленная азотная кислота**.

## 2. Инварианты кодовой базы

**Это главный раздел.** Всё перечисленное неочевидно из кода и нарушается на раз, если не знать.

### 2.1. Индексы пробирок относительны локации

Пробирки лежат в трёх списках: `trayTestTubes`, `workbenchTestTubes`, `fumeHoodTestTubes`
(`src/scenes/laboratory/lib/useTestTubeStorageStore.ts`).
`attachedTubeSlotIndex` в `useBunsenStandStorageStore` — индекс **внутри списка той локации, где сейчас штатив**.
При переносе штатива между локациями индекс обязан пересчитываться в той же операции,
иначе зажим начнёт указывать на другую пробирку или в пустоту.
Единственное место, где это сделано правильно — `src/scenes/laboratory/lib/transferToFumeHood.ts`.

### 2.2. Порядок содержимого пробирки — рабочая величина

`StoredTestTube.contents: readonly string[]` — реактивы в порядке добавления.
Порядок **нельзя** сортировать или схлопывать в множество: из него читаются две ошибки ТЗ —
«нарушен порядок смешивания» и «кислоту льют в воду, а не наоборот».

### 2.3. Камерой владеет только CameraRig

`src/scenes/laboratory/ui/CameraRig.tsx` (~72 КБ) единолично управляет камерой.
Снаружи перелёты **запрашиваются флагами** в `useSceneInteractionStore`, а не вызываются напрямую:
`returnRequested`, `switchRequestedId`, `focusRequestedId`. CameraRig их вычитывает и сам выполняет.

Вызывать `beginCabinetFocus` снаружи нельзя: у вытяжного шкафа перелёт — стадийная последовательность
(`startFocusingFumeHood`: гасит свет и вытяжку, ведёт камеру, поднимает створку, включает свет и вытяжку),
и прямой вызов оставит фазу выставленной без вычисленных координат.

Исключение, уже сделанное: в фазе `cabinetPhase === "inspecting"` камера штатно неподвижна,
поэтому подача вперёд для миниигры нагрева наложена поверх этой позы как смещение вдоль луча взгляда.

### 2.4. Вся калибровка сцены — только в localStorage

Ключи `virtugenium.*` и `vg-*`. Файлового бекапа нет.
`BACKUP_STORAGE_KEY` в `useCameraCalibrationStore` — второй ключ в том же хранилище, а не файл.
Смена браузера, чистка данных сайта или переезд проекта уничтожают всю настройку камеры, мебели,
подноса и штативов. **Экспорт в файл не реализован и очень нужен.**

### 2.5. Новых 3D-ассетов не будет

Проект ведёт один человек, художника нет. Всё, чего нет в `public/assets/models/`,
делается кодом: канвас-текстуры (`createTextTexture`), UV-зоны на меше
(`useFumeHoodControlPanel`), примитивы three.js, CSS-оверлеи.
Существующие `.glb` переиспользовать можно и нужно.

### 2.6. Размеры брать из моделей, а не на глаз

`tests/measure-model.mjs <путь.glb>` печатает габариты, все именованные узлы и позиции пустых якорей.
Ассеты содержат больше разметки, чем использует код. Например, в `PPECabinet.glb` уже есть
`PPE_CoatAnchor [0, 1.4, -0.05]`, `PPE_GogglesSlot [-0.17, 1.68, 0]`, `PPE_GlovesSlot [0.17, 1.68, 0]`,
полка `PPE_TopShelf` с поверхностью на `y = 1.53` и перегородка `PPE_TopDivider`.
В `BunsenStand.glb` — `TubeRing` на `y = 0.22` со смещением `x = 0.104` и `SupportRing` на `y = 0.06`.
Столешница вытяжного шкафа — локальная высота `0.9`.

### 2.7. Шейдер реакции уже написан — но для склянок

`src/scenes/laboratory/lib/reagentMaterials.ts` содержит GLSL с юниформами
`uReactionColor`, `uReactionProgress`, `uCloudiness`, `uTurbulence`, `uTime`, `uEmissionStrength`.
В дев-меню (F8, вкладка Glass / liquid) есть ползунки «Reaction progress», «Cloudiness» и пикер цвета.

Содержимое **пробирки** использует другой, простой материал
(`src/scenes/laboratory/lib/testTubeContents.ts`, обычный `MeshPhysicalMaterial`, без юниформов).
Поэтому «раствор голубеет» — это **перенос существующего шейдера на пробирку**, а не написание нового.

### 2.8. Документ `docs/experiments-context.txt` протух

Описывает опыт 1 как 4 шага и 10 баллов. В коде (`src/data/content/experiments.ts`) — 6 шагов и 34 балла.
Источник правды — код.

## 3. Что реализовано

### 3.1. Сцена

- 360°-обзор с pointer lock, фиксированные зоны, плавная фокусировка, возврат.
- Семь шкафов реактивов и посуды с этикетками, вытяжной шкаф со створкой и панелью управления,
  шкаф СИЗ, рабочий стол, штатив со спиртовкой, поднос.
- **Взятие предметов**: шкаф → поднос → рабочий стол, с анимацией полёта и возвратом на полку.
- **Осмотр склянок** с плесканием жидкости и глубиной резкости.
- Перетаскивание склянок по столешнице со сменой мест и зоной возврата.
- **Наполнение пробирки**: поднести пробирку к склянке — содержимое оказывается внутри;
  у меди гранулы падают по очереди с задержкой.
- **Закрепление пробирки** в кольце штатива по близости.
- Дев-меню F8: освещение, шейдеры, камера, мебель, кнопки, поднос, держатели, зоны реагентов.

### 3.2. Планшет

- Вкладки: Опыты, Этапы, Теория, Ошибки, Уравнение, Признаки реакции, Настройки.
- **Определение веществ**: задание даёт неизвестные («металл X», «жидкость Y»), игрок вводит формулы
  химической клавиатурой, ответ проверяется.
- **Чек-лист «Необходимо»** с прогрессом, часть позиций засчитывается только реальным взятием в 3D.
- **Признаки реакции** — выбор из вариантов, единственное место, где сейчас начисляются баллы помимо шагов.
- **Уравнения** с валидатором (проверка баланса и соответствия целевой реакции) и тестами.
- Экран результата, пороги оценок.

### 3.3. Сделано в этой сессии

- **Перенос в вытяжной шкаф**: кнопка «Перенести» над кнопкой «Назад» в зоне шкафа открывает планшет
  со списком всего, что стоит на столе; игрок выбирает, что перенести. Штатив едет вместе
  с зажатой пробиркой, индекс зажима пересчитывается.
- **Рендер содержимого вытяжного шкафа**: стойка с пробирками, штатив, склянки.
- **СИЗ**: три таблички в шкафу СИЗ по измеренным якорям, надеваются кликом,
  галочкой в планшете больше не засчитываются. Индикатор надетого в углу экрана.
- **Спиртовка**: заглушка из примитивов, размеры выведены из штатива, клик зажигает и гасит.
- **Миниигра нагрева** (переделана 27.09.2026, см. VL-013): клик по штативу → камера подаётся вперёд →
  игрок ведёт кружок за овалом, стекло прогревается по зонам; неравномерно — трещина и штраф;
  после прогрева удержание в пламени греет содержимое.
- **Смешивание**: `contents` вместо одного реактива, перелив пробирка-в-пробирку, наливание из склянки.
- **Дев-кнопка «Опыт 1: всё готово»** — пропускает подготовку, ставит всё в вытяжном шкафу.
- `tests/measure-model.mjs` — измеритель любого `.glb`.

## 4. Что НЕ реализовано

### 4.1. Цепочка опыта не сшита — главная задача

**Сейчас каждый шаг закрывается кнопкой «Выполнить шаг» в планшете, даже если действие физическое.**
Игрок надевает СИЗ, обходит шкафы, зажимает пробирку — и всё равно идёт в планшет отчитываться.
Лаборатория и чек-лист живут параллельно.

Нужно: **шаг закрывается сам, когда условие выполнено в сцене.**
Механизм уже есть — `src/features/tablet/lib/stageSceneConfig.ts` с предикатами над снимком сцены,
но сейчас он только блокирует кнопку, а должен закрывать шаг.
Кнопка остаётся только там, где действие правда в планшете: определение веществ и уравнение.

Подзадачи:

1. Эффект «предикат стал истинным → `advanceStep`» (`src/features/tablet/lib/stepActions.ts`).
2. **Предикат для `step-1-experiment`, которого нет вообще**: в зажатой пробирке и медь, и кислота,
   причём медь добавлена раньше кислоты, и нагрев доведён до конца
   (`useHeatingStore.phase === "done"`). Сейчас шаг закрывается кнопкой, даже если игрок ничего не делал.
3. Предикат для `step-1-ppe`: собрано 8 из 8.
4. Сделать штатив и спиртовку физическими, как медь и пробирки — сейчас они отмечаются галочкой,
   хотя штатив реально берётся и лежит в `useBunsenStandStorageStore.onWorkbench`.

### 4.2. Штрафы — частично (обновлено 27.09.2026)

Правила — `docs/decisions/VL-013-experiment-rules.md`. Механизм:
`applyErrorRule` (`src/features/tablet/lib/penalties.ts`) списывает баллы по `errorScoreRules`
(раз за попытку), пишет во вкладку «Ошибки»; плашка сверху — `useLabNoticeStore` + `LabNoticeOverlay`.
Все наливания в пробирку идут через `tryAddToTube` / `tryPourBetweenTubes` (`pourIntoTube.ts`),
правила порядка — `mixingRules.ts`.

Работают: порядок смешивания (`error-1-pour`), трещина при неравномерном прогреве (`error-1-heat`),
«нельзя слить» для чужих реактивов, нагрев невозможен без держателя.
**Не подключены:** `error-*-no-ppe`, `error-1-fume`, `error-*-equation` (последние пишутся
планшетом по-своему — проверить), ориентация этикетки (отложена вместе с механикой наливания).

### 4.3. Баллы не сходятся

Сумма всех `successScoreRules` опыта 1: 3 + 2 + 2 + 2 + 9 = 18, плюс признаки реакции 4 = **22**.
`maximumScore: 34`. Двенадцати баллов не начисляет ничто.
Вероятно, не оценивается шаг «определить вещества» — у него пустые `successScoreRules`.
Требует решения от автора химической части.

### 4.4. Визуальных признаков реакции нет

Ни голубого раствора, ни бурого газа, ни осадка. При этом в планшете игрока спрашивают,
какие признаки он наблюдал. См. 2.7 — шейдер для этого уже есть, его надо перенести на пробирку.
Бурый газ NO₂ — единственный по-настоящему новый эффект.

### 4.5. Опыты 2, 3, 4

Данные полные (шесть шагов, уравнения, признаки, пороги), но:
`STAGE_REQUIRED_ITEMS` содержит только ключ `step-1-ppe`, предикатов сцены нет.
После того как опыт 1 будет сшит, остальные — в основном данные,
так как все три построены на сливании растворов, а механизм перелива уже есть.

### 4.6. Прочее

- **Три режима** (`AppMode = "training" | "classic" | "clean"`) объявлены, лежат в сторе, есть в тестах —
  и не влияют **ни на что**.
- **Звука нет совсем**: ни одного аудиофайла, ни одной библиотеки.
  `useSettingsStore` хранит громкость и честно пишет, что играть нечему.
- **Экспорт калибровки в файл** — см. 2.4.
- **Git в системе не установлен**, папка `.git` есть, история недоступна.

## 6. Правила для исполнителя

1. **Не изобретать второй способ делать то, для чего уже есть первый.** В проекте сложились
   соглашения: сторы zustand с подробными комментариями, `deferredDispose` для three.js-ресурсов,
   `ReagentHoverRim` для подсветки, канвас-текстуры для текста на геометрии, request-флаги для камеры.
2. **Никаких новых `.glb`.**
3. **Размеры — из `tests/measure-model.mjs`**, не на глаз.
4. Прежде чем хардкодить смещение внутри модели — проверить, нет ли там готового якоря.
5. Комментарии в этом проекте объясняют **почему**, а не что. Много из них описывают уже
   совершённые ошибки и откаты — читать их перед правкой соответствующего места.
6. Проверять работу: `npm run typecheck`, затем `npx vitest run --no-file-parallelism`, затем `npm run build`.
