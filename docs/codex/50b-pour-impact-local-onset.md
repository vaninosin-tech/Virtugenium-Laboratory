# Задача для Codex: количества, объём, налив, встряхивание — общий слой (50b, часть задания 50)

Обязательные документы: `docs/realism/chemistry_four_experiments_corrected.md`,
`docs/realism/local-reaction-onset.md`, **`docs/realism/game-rules-amounts.md`** (решения заказчика по
объёмам, избыткам, меди, встряхиванию, времени). План — `docs/codex/cu-hno3-plan.md`.
Порядок заказчика: 45–48 → 49 → 50 → 51; это часть 50. База — коммиты до feaa72c + задание 50 (BaSO₄).

## Что сейчас (по коду)
- `useTestTubeStorageStore`: содержимое пробирки — **список id реагентов**, без количеств.
  `pourIntoTube.ts → tryAddToTube` **отказывает в повторном наливе того же реагента**
  (`contents.includes(reagentId)`), налив всегда целый.
- Налив в лапку: анимация `StandMotion.tsx` / `useStandMotionStore.pour` (`POUR_MS` = 1.7 с), реагент
  кладётся в список одним моментом. Струя — `ui/PourStream.tsx`. Налив на столе — по близости пробирки к
  склянке, без струи.
- `tubeReactionVisuals.ts`: «налив» — `options.pour: boolean`, внесение растянуто на 1,3 с (`pourAge`),
  уровень по таймеру из `testTubeLiquidFill(liquidCount)`.
- Опыт 1: медь растворяется **полностью** (кинетика `tubeReactions.ts` по `progress` до 1).

## Что сделать
1. **Учёт количеств (новый модуль в `lib/`, напр. `tubeAmounts.ts`)** — по пробирке: объём жидкости (мл),
   количества веществ в условных единицах (отдельно от объёма), остаток меди. Начальные/добавочные
   количества по `game-rules-amounts.md` §1–2 (2,5 мл начально, 1,0 мл полная добавка, вместимость 5,0;
   избытки: HNO₃ ограничивает так, что остаётся 40–50 % меди; Ag⁺ +15 %; Ba²⁺ +10 %; сульфит в
   умеренном избытке, H⁺ хватает). Список `contents` **не менять** (его читают планшет и `mixingRules`) —
   учёт идёт параллельно, по `instanceId`.
2. **Налив — фиксированная порция по клику ЛКМ** (решение заказчика): один налив = 1,0 мл через
   существующую анимацию (`StandMotion.tsx`, автопозиционирование) — механику не менять. Порция
   поступает постепенно по фазе струи (расход из толщины струи), сумма за налив = 1,0 мл (с учётом
   вместимости 5,0). Внутри учёта — функция `deliver(tubeId, reagentId, ml)`; поведение `tryAddToTube`
   не менять.
3. **Канал попадания струи** (store в `lib/`, пишет `ui/PourStream.tsx`): точка попадания в жидкость в
   системе пробирки, расход (мл/с по фазам толщины струи), направление/импульс, реагент. Для налива на
   столе (без струи) — точка у стенки со стороны склянки и стандартный расход.
4. **Объём и уровень**: уровень и маска 3D-полей растут на фактически поступивший объём (интеграл
   расхода), не по таймеру; поля и продукты сохраняются; без выливания (§6).
5. **Локальное внесение**: реагент вносится в клетки у точки попадания с импульсом ∝ расходу (медленно —
   компактно, быстро — дальше и сильнее течения). Перевести опыты 3 и 4 и внесение кислоты в опыте 1.
6. **Опыт 1 — кислота ограничивает**: R1 расходует учётную HNO₃ (8 на 3 Cu); реакция затухает при её
   исчерпании; остаётся 40–50 % массы меди; геометрия гранулы — от остатка меди. `progress` для планшета —
   доля израсходованной кислоты (дойдёт до 1, медь останется). Тексты планшета («жидкость над осадком»)
   этому соответствуют.
7. **Встряхивание без кнопки** (§4): ускорение и угловая скорость пробирки из её мировой матрицы по
   кадрам → импульсы в `VelocityField` (с порогом, без реакции на мелкую дрожь), ускоренное смешивание,
   подъём части осадка (сделать общий механизм, конкретику AgCl — в 51; BaSO₄ — взвесь снова расходится).
8. **Ускорение позднего оседания** (§5): коэффициент только при спокойной жидкости (низкая кинетическая
   энергия поля), BaSO₄ до ×4 (AgCl до ×3 — в 51), плавный возврат к ×1 при движении/наливе. В
   `tubeSimulationConfig.ts`.
9. **Страховка планшета** для опыта 4 (как в опыте 3): поле не обновлялось >1 с — `progress` идёт по
   простой кинетике.
10. **Песочница** (`sandbox/setupSandbox.ts`, `SandboxPanel.tsx` — мои, менять разрешаю): синтетический
    налив с выбором точки (левая стенка / центр / правая) и силы (медленно / быстро) и объёма (стандартная порция 1,0 мл).
