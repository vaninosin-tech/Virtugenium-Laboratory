# Wave 15 R2 report

## Files and output

- `tests/_wave15/baselineRecord.mjs` records the real stand actions with installed Chrome. It sets stage 3, aggregation off, no jet/subgrid flags by default. `BOTH=1` records wide and close cameras in separate runs. The default wide camera is `{dist:0.42,fov:30,targetY:-0.045,targetSide:0.02}`; close is `{dist:0.2,fov:20,targetY:-0.115,targetSide:0}`. The script waits for a captured screencast frame, then at least 1.5 s of simulation before the NaCl click, and continues until 14 s of simulation afterward. `SLOW=0.15` dilates only the page's `Date.now`. The overlay prints true simulation time, valid events, delivered volume, fine mass and occupied depth. UI hiding follows `_trace.mjs` and is on unless `HIDEUI=0`. Frames and `frames/index.json` retain CDP epoch timestamps; `trace.json` has `clickSim`, `trace`, full `dumps`, `diag`, source accounting and crop/camera metadata. `frames/simulation.ffconcat` uses nearest in-page `performance.timeOrigin + performance.now()` records to place each frame on the simulation clock. ffmpeg makes a variable-rate, continuous `baseline.mp4`. The raw frames remain available to inspect any failed stage.
- `tests/_wave15/comparisonCore.mjs` and `buildComparison.mjs` extract the reference at 5 FPS (0.2 s), detect its bright vertical tube, compute whiteness fraction, luminance variance, white front, and top/middle/bottom bright mass, and compute the same measures on the game tube crop. Full-field dumps cross-check occupied fraction, coefficient of variation, and occupied depth. A 0.35 whiteness fraction marks the visual milky stage. Monotone dynamic time warping aligns game and reference using whiteness fraction plus front position. `alignment.svg` plots game simulation time against reference playback time. The three-panel `comparison.mp4` shows reference crop, real-game frame, and fixed-scale center slice of the raw fine suspension. The game frame is joined to an in-page record by epoch, never by frame number. The reference's x5/x50 playback time is not treated as chemical time. `X50_AT=<reference playback seconds>` supplies the observed label switch for the burnt-in label; otherwise it reads `x5/x50`, avoiding a fabricated switch point. The field panel defaults to a fixed 0.005 full-white scale; set `FIELD_SCALE` explicitly to change it. `METRICS_ONLY=1` skips panel rendering.
- `tests/_wave15/runBaseline.mjs` prints and runs each browser/ffmpeg task in a separate process, then reads the FPS summary and warns without failing if cloud-on median FPS is below 44, 10th percentile FPS below 33, or peak frame exceeds 220 ms. `PLAN_ONLY=1` prints the sequence. The sequence includes the existing in-liquid cloud-on/off pixel validation, full-field recorder, strict regression, and pour FPS harness.
- `tests/_wave13/recordRun.mjs` now stores the tracer selector as `diagSelector`; runtime diagnostics keep the `diag` name. `regressionAB.mjs` accepts both old and new recordings. `regressionChecks.mjs` treats an absent pre-impact field as zero and records a note, checks Ag+ plus product and Cl- plus product at every dump to 1e-9, and rejects nonzero species, source, tracer, or fine concentration in dry cells. Source volume is taken from the mounted app's `window.__diag.sourceAccounting()` by the recorder.
- `tests/night/wave15r2/comparison.test.ts` tests synthetic crop metrics, field metrics, stage alignment, labels and markers, the absent-field regression rule, and an existing `frames/w12D/frames/index.json` format.

## Long frame at NaCl click

The likely cause of the reported roughly 220 ms first-click frame is shader warm-up. `runStandAction` calls `warmSilverShaderForStand` on the NaCl click (`standTableActions.ts:162`), which schedules `prewarmBariumLiquidShader` work at zero delay. That work clones and fills a preview tube, calls `renderer.compile`, renders the live and dark scenes multiple times, then calls `gl.finish()` (`tubeReactionVisuals.ts:348-357, 367-459`). Those operations can block the next frame. The first runtime `TubeSilverField("LOW", ...)` construction and synchronous `advance` occur only on the first valid impact (`tubeSilverRuntime.ts:50-91`), roughly 600 ms after click, so they do not explain a spike immediately at click. `PourStream` creates its 13-by-8 stream geometry through `useMemo` at component mount (`PourStream.tsx:20-46,155`), not on that click. This is a code-path hypothesis: a browser timing trace is needed to attribute the spike definitively. No Node constructor benchmark was claimed because the field is not the leading hypothesis and the browser timing point was unavailable.
